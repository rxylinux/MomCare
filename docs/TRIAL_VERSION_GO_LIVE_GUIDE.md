# 体验版上线与两人使用全流程指南

**适用范围**：不上架、不审核，仅本人（管理员）与妻子两位成员通过**体验版**长期使用。
**依据**：`cloud/DEPLOY.md`（工程既定部署方案）、`cloud/collections.json`（集合与索引权威清单）、2026-09-20 裁定（仅体验版）。
**诚实边界**：微信控制台界面与价格可能随时间变化，涉及控制台的步骤以实际界面为准；本文不含任何未经工程验证的承诺。

## 阶段 0：准备（10 分钟）

1. 下载安装**微信开发者工具**（稳定版，微信官方官网下载，macOS 版）。
2. 用你本人的微信扫码登录开发者工具。
3. 两台手机确认微信可正常使用；你老婆无需安装任何东西。

## 阶段 1：开通云开发环境（10 分钟）

1. 打开 mp.weixin.qq.com 小程序后台（或开发者工具内「云开发」入口）。
2. 开通**微信云开发**，创建环境（按量付费基础套餐，目前基础版 19.9/月——**以购买页当前价格为准**）。这是本项目唯一的持续费用（约 240/年）。
3. 创建完成后，记录**环境 ID**（形如 `momcare-1a2b3c` 的字符串，控制台环境信息处可查）。它不是密钥，可以入库存档。
4. 注意：环境与 AppID 绑定，一个环境即可，不要创建多余的。

## 阶段 2：填环境 ID 并构建（5 分钟）

1. 编辑 `utils/cloudConfig.js`，把 `envId: ''` 填成阶段 1 记录的环境 ID（`appId` 已配好，不用动）。
2. 构建：

   ```sh
   npm run build:mp-weixin     # 小程序产物 → dist/build/mp-weixin
   npm run assemble:cloud      # 云函数部署包 → dist/cloud-functions/
   ```

3. 自检：`npm test`（phase-d 发布准备套件应全绿）。

> 这两步是纯本地操作，可以让我（ZCode）代跑并核验产物。

## 阶段 3：创建集合与安全规则（20–30 分钟）

**集合（24 个，以 `cloud/collections.json` 为权威清单，索引按其中每个集合的 `indexes` 字段创建）**：

| 分组 | 集合 |
| --- | --- |
| B1/B2 基础 | mc_shared_records、mc_private_notes、mc_operations、mc_files |
| B2a 档案 | mc_pregnancy、mc_health_daily、mc_moods |
| B2b1 产检/待产包 | mc_checkups、mc_bag_items |
| B2b2 报告 | mc_reports |
| B3b 隔离恢复 | mc_restore_batches、mc_restore_declare_chunks、mc_restore_declarations、mc_restore_anchors、mc_restore_records、mc_restore_record_chunks、mc_restore_files、mc_restore_slot_locks、mc_restore_blocks |
| C 协同 | mc_shared_needs、mc_family_tasks |
| E 工具 | mc_fetal_sessions、mc_contraction_records、mc_efw_records |

操作：云开发控制台 → 数据库 → 逐个「新建集合」（同名、不区分大小写需完全一致）→ 每个集合在「索引管理」里按 `collections.json` 的定义添加复合索引。

**安全规则（两项都要）**：
- 数据库 → 安全规则 → 粘贴 `cloud/rules/database.rules.json` 内容（客户端零直接读写，全部经云函数——这是工程的安全设计，不要改宽）。
- 存储 → 安全规则 → 粘贴 `cloud/rules/storage.rules.json` 内容（默认全部拒绝；报告图片上传通道**有意保持关闭**，见阶段 9 可选项）。

## 阶段 4：部署云函数（30–60 分钟，首次较慢）

产物：`dist/cloud-functions/` 下 10 个目录（mc-collab、mc-files、mc-health、mc-identity、mc-private-notes、mc-reports、mc-restore、mc-schedule、mc-shared-records、mc-tools），每个含锁定的 `wx-server-sdk@4.0.2` 依赖声明。

**上传方式（任选其一）**：
- 开发者工具：在 dist/build/mp-weixin 项目的 `project.config.json` 中加 `"cloudfunctionRoot": "cloudfunctions/"`，把 10 个函数目录复制到 `dist/build/mp-weixin/cloudfunctions/` 下，右键每个目录 →「上传并部署：云端安装依赖」；
- 或云开发控制台 → 云函数 → 逐个新建并上传代码（云端安装依赖）。

**环境变量（先只配前两项！成员 OpenID 此时还没有）**，每个函数都要配：

```
MC_APPID=wxf3b1d079e04cb490
MC_FAMILY_ID=fam-momcare
```

**部署后自检**（控制台云函数测试或开发者工具本地调试）：

```js
mc-identity {}   // 预期 { ok:false, code:'not-configured' } 或 'not-family-member'
```

看到明确失败是**正确**的：工程是 fail-closed 设计，缺配置绝不伪造成功。

## 阶段 5：上传体验版（10 分钟）

1. 开发者工具 → 导入项目 → 目录选 `dist/build/mp-weixin`（AppID 已在 project.config.json）。
2. 模拟器能打开、无红色报错 → 工具栏「预览」→ 你自己手机扫码，确认真机能打开（此时云功能会提示"尚未配置成员"，正常）。
3. 点「上传」，版本号 `1.0.0`，备注随意（如 trial-first）。
4. mp 后台 → 管理 → 版本管理 → 开发版本 → 把刚上传的版本**设为体验版**。

## 阶段 6：后台设置（15 分钟）

1. **加体验成员**：mp 后台 → 成员管理 → 体验成员 → 通过微信号把你老婆的微信添加为体验成员。
2. **《用户隐私保护指引》**：后台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 如实勾选申明：用户信息（OpenID）、相册/摄像头（拍照上传报告）、健康记录。不勾任何与实际不符的项，提交。**不填这项，相机/相册类接口在运行时可能被拦**，这不是可选项。
3. 把体验版二维码发给你老婆。

## 阶段 7：两人首次使用 + OpenID 录入（15 分钟）

1. 两人各自扫体验版二维码打开小程序 →「我的 → 家庭共享（云）」→ 点「**查看我的 OpenID**」。
2. 各自把屏幕上的 OpenID 抄送给你（这个动作服务端只校验 AppID、只返回本人 OpenID，安全）。
3. 你在云开发控制台给 **10 个函数**补齐环境变量并保存：

   ```
   MC_MEMBER_MAMA_OPENID=<你老婆的 OpenID>
   MC_MEMBER_PAPA_OPENID=<你的 OpenID>
   ```

   （注意谁对应 mama/papa 由你们自己定；`MC_FAMILY_ID` 全家同一个即可。）
4. 两人各自杀掉小程序重新打开 →「家庭共享（云）」应显示**妈妈/爸爸**两个成员身份。
5. 可选加固验证：找第三台手机（任何非成员微信）打开 → 应显示"仅限本家庭成员使用"。

> 工程里**不存在自动注册**：环境变量是唯一成员来源，"最先登录自动成为成员"从未实现也明确不做。所以 OpenID 必须走上面这个流程。

## 阶段 8：双手机验收（30–60 分钟，两人一起过）

按这个顺序走一遍核心闭环，每步两端都看一眼：

1. **建档**：你老婆端填 LMP/预产期 → 保存 → 你端下拉刷新能看到同样孕周。
2. **每日记录**：共享数字（体重/血压/胎动）一端写、另一端可见；两端同时改同一条 → 后保存方收到"已被对方更新"冲突提示。
3. **私人隔离**：各自写一条私人心情/笔记 → 对方**完全看不到**（连存在性都看不到）。
4. **产检**：自动模板生成 → 勾选项目、完成、跳过；一端完成另一端同步。
5. **待产包**：新增/编辑/勾选，负责人字段两端同步；关联共同任务只有一条不重复。
6. **分享与任务**：老婆发一条分享需求 → 你接单成任务 → 完成/撤回，两端状态一致。
7. **计时器**：胎动计数、宫缩计时（含紧急联系人入口）各跑一次。
8. **B 超估重**：录入双顶径/腹围/股骨长任一组合 → 出估计值并存档。
9. **饮食速查**：搜一个食物（如"螃蟹"）→ 级别与说明正常显示；AI 咨询显示"未配置，请遵医嘱"（**这是预期的诚实降级**）。
10. **知识库**：列表、分类、搜索、详情秒开（全离线）。
11. **报告页**：此时显示"上传通道未启用"——**预期行为**（安全默认，见阶段 9）。
12. **异常路径**：飞行模式下写记录 → 恢复网络 → 待办自动补传不丢不重；中途切后台/杀进程再进，状态不乱。

## 阶段 9：日常使用与维护

**更新版本**（以后改了代码）：
改代码 → `npm run build:mp-weixin` → 开发者工具上传新版本 → 后台把新开发版本设为体验版 → 两人下次打开自动是新版（体验版更新即时生效，无审核）。

**数据备份**：
定期用工程内 B3 的**完整导出**功能把数据导出到手机本地（含附件实体，不是只有 JSON）——云环境欠费停服时的数据生命线。建议每月一次。

**续费**：
云开发费用到期会影响数据可访问性，留意扣费；不用了就先导出数据再停。

**可选项 A——开启报告图片上传**（需要时再做）：
默认关闭是工程的安全设计（客户端直传需验证暂存目录规则后才能开）。开启步骤：控制台验证 `cloud/rules/storage.rules.staging.example.json` 的本人目录限定写法 → 确认实际拒绝用例 → 更新存储规则 → 开放上传。**建议先用一两周基础功能稳定后再做。**

**可选项 B——AI 解读与报告 OCR**（可以永远不做）：
- 给 mc-tools 配 `DEEPSEEK_API_KEY` 即启用报告 AI 解读与饮食 AI 咨询；不配则永远显示"未配置，请遵医嘱"，所有基础功能不受影响。费用走 DeepSeek 自己的账户。
- 再配 `MC_OCR_PROVIDER=wechat` 即启用**报告图片 OCR 提取**（微信云调用 OCR，无需额外账号/密钥）：解读会基于附件照片识别出的文字逐项分析，并在解读页显示"报告原文提取（OCR）"供核对。不配则解读仅基于元数据（日期/类型/备注）。
- 两项配好后把 **mc-tools 函数超时调到 ≥90 秒**（控制台 → 云函数 → mc-tools → 配置），OCR+解读全程可能超过默认超时。
- 依赖关系：要 OCR 识别真实报告照片，须先开启可选项 A（上传通道）——没有附件就没有图可识别；只开 A 不开 B 也完全可用（原件阅读）。
- **隐私指引需补充**：报告图片将经微信 OCR 服务（腾讯体系）提取文字、解读文字送 DeepSeek 处理——在《用户隐私保护指引》如实补充第三方处理说明后再启用。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 全程显示"尚未配置" | `utils/cloudConfig.js` 的 envId 没填，或填错；重新填 + 重新构建上传 |
| 云函数返回 not-configured | 环境变量四件套没配齐（MC_APPID / MC_FAMILY_ID / 两个 MC_MEMBER_OPENID），10 个函数都要有 |
| "仅限本家庭成员使用" | OpenID 没配或配错（注意 mama/papa 别填反）；改完环境变量需重新打开小程序 |
| 报告页"上传通道未启用" | 正常，见阶段 9 可选项 A |
| AI 处处"未配置，请遵医嘱" | 正常，未配 DeepSeek Key 的诚实降级 |
| 解读没读图（只基于日期/备注） | 正常，未配 `MC_OCR_PROVIDER` 或报告无附件；配 OCR 前先开上传通道（可选项 A） |
| OCR 解读中途报"OCR 识别失败" | 照片模糊/服务波动：重拍清晰照片重试；仍失败以原件为准（如实失败，不伪造解读） |
| 体验版二维码失效/旧版本 | 重新上传后在后台重新设为体验版，取新二维码 |
| 一端改了另一端看不到 | 下拉刷新；仍无 → 查网络；再无 → 反馈给我查 |
| 本机跑测试偶发段错误 | 已定案的 Node 引擎问题，与小程序无关，重跑即可（2026-09-20 裁定：忽略） |
