# MomCare 修复设计与验收契约

对应计划：`REPAIR_PLAN_2026-10-01.md`。任何实现偏差需交接中说明，由 Codex 审核；未验证的云平台属性不得当安全依据。

## R1：入口身份、可靠保存、成员隔离、提醒日期

### 推送入口

`event` 为不可信业务输入，Type、TriggerName、kind 均不能授权。手动 sendNow 必须走现有白名单身份认证。定时触发必须依据平台逐次调用提供的可信上下文，来源语义要有本机 SDK 源码或官方文档证据；不能把 event 挪到另一个同样可伪造字段，也不能依赖容器上一次请求遗留环境变量。未知来源拒绝，拒绝发生在读数据库、外呼前。若本地 SDK 无法证明定时身份，先 fail closed，明确记录定时部署门槛，不为保持功能绕过认证。已证明的平台定时上下文还需匹配允许的两个触发器名。手动 eve 的 kind 只在认证后起作用。

推送日期统一上海日期。前夜查“明天有效 pending 产检”，不以最早过期 pending 决定是否发送。日常提醒保留现有内容策略，但查询必须稳定排序且遍历 tombstone，不能 limit(20) 后猜完整。数据库失败应给明确错误，不装作明天无产检。

### 工具本地持久化

保存函数必须消费 writeJson 的布尔/异常结果。只有持久化成功才允许 offline-pending；失败保留内存草稿、提供明确未保存状态，禁止诱导用户清空草稿或以云端结果遮掩未保存本地数据。不同持久化步骤有部分成功时报告真实状态，留重试数据。初始化/恢复不得把不可读缓存当空白成功。

缓存身份至少包含环境、家庭、成员；RAM 的 active scope 及所有异步操作捕获 session epoch。logout、成员/家庭/环境切换立即停止旧作用域展示及自动重试。异步结果只能写回原作用域，不能污染新身份。旧无作用域缓存默认隔离保留；不得自动分配给当前成员或上传。scope 不完整时不写、不云请求。页面 draft/计时器/同步进度需一并处理，不能只改 storage key。重试必须以记录所属 scope 与当前会话一致为前置条件。

## R2：AI 输入快照与完整性

发起分析时捕获报告身份、revision 和实际输入（note、附件列表及影响分析的元数据）的摘要。保存需原子 compare-and-set：读取初始状态后遇到任何编辑/删除/附件变更即拒绝写旧结果。不能先 get 对比再无条件 update；需数据库事务或等价原子条件写。结果保存与响应 revision 以实际提交为准，标注输入版本、输入摘要、模型及分析覆盖范围。重复/并发分析也需避免互相覆盖。前端清楚表达过期/未完成，保留已有有效结果。

调用 DeepSeek 的生产解析路径必须检查 choices、message.content 及 finish_reason；仅明确完整终止的结果可成功。length、content_filter、缺失/未知终止原因、供应商错误、畸形响应均返回受控失败，不保存新“有效”分析。不同供应商按各自真实完成字段设计，不机械套用。mock 注入真实 HTTP/SDK 解析入口，不能只测替身 helper。图片只分析前 3 个时，页面必须披露“已分析 x/y 个附件”，结果 provenance 列出分析/未分析附件，失败与未覆盖不能显示为完整分析。

## R3：实际报告字段与完整分页

导出报告投影须与真实服务写入 schema 一致，纳入 ai_result、ocr_result、vision_result 及本次新增 provenance/coverage 的允许格式。明确大小、类型、危险键约束，保持已有 canonical 字节及 schema 兼容，不通过去掉未知字段检查或丢弃合法结果“修复”。供应商原始秘密/调试内部状态不得导出。未知字段、不可读 pending、身份变化与完整性失败仍需诊断/拒绝。使用真实 mc-tools 生成的记录做 export 和已有 validator 往返验证；新增字段对恢复是否支持如实注明，不能暗示完整恢复已完成。

工具列表游标基于数据库实际扫描顺序而非过滤后结果，稳定排序包含唯一键作为 tie-breaker。可把合法过滤条件下推，但不能因连续墓碑/异常记录超出 overfetch 窗口而提前结束。单次扫描设预算时返回可继续游标及真实 hasMore，即使当前页为空；客户端继续拉取并防止重复/不前进游标，无静默无限循环。pullContractions 遍历全部页、正确去重并保留本地 pending；会话切换中止旧 scope。
