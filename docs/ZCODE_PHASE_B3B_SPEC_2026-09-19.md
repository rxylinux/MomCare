# B3b 实施约束补充：完整备份与隔离恢复

状态：Codex 方案补充。B3a 验收后，由 ZCode 先更新 B3 DESIGN 的协议/矩阵并经 review，再开始本阶段编码。未部署；不读取真实旧数据；不向聊天发送真实文件。

## 已确定的格式和平台边界

沿用单一 `.mcpkg` 有界二进制容器（24 字节固定头、UTF-8 manifest、按序长度前缀文件段）。所有业务域 schemaVersion 精确匹配；魔数/版本/保留字段/安全整数/偏移/长度/尾部/重复路径或 ID/引用关系全部校验。用户包内路径只作逻辑标识；物理临时文件名由程序生成。

应用初始上限：包总长 64 MiB，manifest 4 MiB，文件项 500，总记录 10000；附件单项沿用 mc-files 10 MiB，单领域 JSON 4 MiB。以上是可调整的应用边界，不宣称微信平台容量保证。超限必须停止并提示具体范围，不能截断后宣称完整。最终真机阶段另测设备空间与实际容量。

微信导出以顺序追加/分块读取构建文件，校验回读仍按块，禁止一次读取全包。纯 JS 增量 SHA-256 和 UTF-8 兼容层不得依赖 Node 的 Buffer/crypto 或未经验证的平台全局。H5 使用同一个 codec，文件输入用 slice 分块；Blob 下载只在用户主动操作下产生。代码加载时不得在微信触发 DOM/Blob 路径。

导出状态区分：构建中、已生成且校验通过、交付动作成功、用户取消、失败。微信由用户点击 shareFileMessage 并在微信界面选择收件人；代码不自动选聊天。H5 下载触发仅表示浏览器已接收下载操作，不声称备份已永久保存。缺平台能力如实说明；不拿相册或沙箱路径当完整可搬移备份。

## 清单必须能还原记录和原件

清单除当前 B3 DESIGN 字段外，须明确定义：

- 每个领域 JSON 的 fileIndex、schemaVersion、记录数；共享与本人私人范围。
- 报告附件逐页映射，至少包含 reportId、按顺序的 `{ originalFileId, fileIndex }`。多报告可共享同一文件段，顺序不依赖文件名或 sha 排序。
- 文件段包含实际长度、SHA-256、媒体类型。originalFileId 只用于包内索引，不用作云端授权或恢复的新 fileId。
- 每个记录的稳定 ID/版本、每个领域的实际分页完成标志。未知/缺失域不能被空数组掩盖；无记录的域也须明确声明。
- pending/conflict/local unsent drafts/upload batches/migration incomplete 的检查范围。对无法纳入云端全量包的未同步输入给出明确待处理列表；禁止只查一个 pendingCount 就宣称全部数据已备份。

从真实服务端完整分页读取孕期、日健康、私人心情（仅本人可选）、产检、待产包、报告，并经受控报告读取接口取得所有原件。不得只打包 familyStore 局部缓存。交付前重查身份、授权、版本和墓碑；对变化进行有界重试或标明未完成。不得宣称跨集合原子快照。记录字段严格白名单，备份不含旧 token/OpenID/会话/配额/临时 URL。

## 恢复输入和服务端协议

恢复写入 `mc_restore_*` 隔离集合，首页/健康趋势等实时域不读取这些集合。本期不实现 merge，也不新增永久清理界面。现有或已删除正式记录只显示差异，不覆盖或复活。

具体动作由 ZCode 在设计中定名，但必须覆盖以下职责：

1. begin：可信当前成员创建批次，绑定不可变 package/manifest 摘要、格式、领域范围、预期条目/附件映射及数量。服务端不能只信最终记录数：需有可逐项核验的内容声明。manifest 较大时用有序、有大小上限的分片上传并在服务端重组校验摘要，不能全包或无界 manifest 放单个请求/数据库文档。
2. uploadRecord：每条规范化记录对应预声明的稳定 domain/id/index/hash；服务端验证白名单/schema/字段/私人范围，不允许同索引换内容。分页存储隔离记录，重复同内容幂等。
3. uploadAttachment：客户端先用 prepareUpload → wx.cloud.uploadFile → registerStaged 传实际字节；恢复接口只接收登记 fileId 与包内索引/摘要/长度/关联报告。服务端校验当前家庭/当前成员的文件归属、登记结果及实际字节；禁止 base64 整图塞云函数、任意 URL 下载、信包自带 cloud fileId。
4. attach/commit：隔离附件引用与文件状态事务一致，registered 才能引用，cleaning/deleted 拒绝。恢复引用也阻止 B2b2 孤儿清理。不能仅使用裸 fileId 公开下载隔离原件；新增读取路由同时校验批次 owner、引用、状态和当前授权。
5. commit/verify：只有所有预声明条目和原件精确齐全、映射有效、摘要符合才完成恢复。设计明确哪个动作将哪个状态推进到 restored；部分失败/丢响应/重启/重复提交不提前成功。分步校验使用版本或不可变冻结约束，避免边校验边改内容。
6. list/preview/verify：批次元数据、记录、文件 URL、错误、幂等重放都按可信 owner 过滤；混合私人内容的批次不得因 family 相同被另一成员枚举。包内 createdBy/familyId/owner 是来源说明，不能代替当前授权；私人作者仍须本人明确确认。

客户端在任何副作用前持久化不可变请求意图及稳定 ID；恢复清单失败停止发送。每个 await 后核对发起 epoch。失败输入保留，提供重试入口；不自动删除原包或用户原件。新环境映射独立，不沿用旧环境可信标志。

## 独立验收必须能复现

实际 privacy → export/import 页及处理器、共同 codec、平台适配器、真实云函数链都纳入永久测试。需导出一个含多领域和至少三张有效原件的样例包，在全新 store/session 中重新加载、验证、上传到隔离域，逐条字段/每页顺序/字节/大小/SHA256 精确对比，并实际解码图片；正式集合保持不变。

另测：中文/emoji UTF-8、块边界、超限/损坏/短读/缺件/未知版本/重复 ID/非法路径/错映射、相同包重复恢复、同 ID 不同正文、磁盘满/网络失败/登记丢响应/中途退出、双身份切换、私人 canary、错误/冲突/重放旁路、恢复引用与孤儿清理竞态。微信适配器用忠实文件 API 合约验证；H5 页面实际选择/生成同一包。模拟通过不冒充真机完成。
