状态：B2a R5 已经 Codex 本地独立验收，**阶段提交完成后启动本方案**。这只是把原 B2b 分为两个较小 review 单元：B2b1 产检/待产包，B2b2 报告/附件。不新增功能范围，不提前部署。ZCode 实现，Codex 独立 review，通过后提交推送。

先读 `DELIVERY_STATUS.md`、`REMAINING_PHASE_ACCEPTANCE.md`、DESIGN 和 B2a 已验收交接。沿用 B2a 的权威身份、版本、持久待办与隔离缓存；不得复制出另一套稍有差别的同步规则。若需改公共模块，先列出兼容影响，再保留原回归。

## 实际入口

- `pages/profile/checkup-reminder.vue`：下一次产检、倒计时、检查项目勾选、完成/跳过和历史。保持已有入口，补共同医院/时间、陪同、材料与问题的可编辑内容。
- `pages/profile/hospital-bag.vue`：分类、列表、进度、添加/删除/准备状态。补数量、存放位置、负责人，双方读写同一条目。
- 首页/我的展示对应共享数据；所有弹层、统计、历史和空状态都要接同一源。以实际 SFC 处理器/模板绑定测试，不能仅看 store 有对应方法。

## 领域与版本约定

1. 使用稳定实体 ID；产检同周可多条，待产包同名也可多条，不能以周数/名称作为唯一用户记录 ID。模板条目有稳定 templateKey，用户条目有独立 ID。
2. 文档包含 familyId、schemaVersion、revision、deleted、updatedBy、updatedAt。服务端生成操作者；owner/assignee 是责任分配字段，不能充当授权。私人症状/备注不自动进入共同产检问题。
3. 每条产检包括日号、可选时间/医院、明确 pending/completed/skipped 状态、稳定项目 ID 的检查清单、陪同/材料/问题。每条待产包包括名称、分类、正数量、位置、负责人及准备状态。字段白名单、长度、枚举和空值语义需明示并校验。
4. 各页打开编辑时捕获实体版本与字段基线，后台刷新不改用户输入或提高提交版本。检查项目的变化是明确项目 ID 的操作；删除/重排不能把旧数组索引落到另一个项目。
5. 分页按稳定唯一排序与游标，读取包括墓碑。按日期排序的产检必须有 ID 作为同日排序第二键；待产包也不能靠更新时间相同而漏页。只在完整拉取成功后显示完整同步时间。
6. pending 操作走 B2a 的持久协议；如果扩展 kind/实体路由，所有 retry、adoptCloud、resubmit、计数、成员切换与失败分支都要覆盖新增领域，不能只有 enqueue 成功。

## 模板和日期变更

- 空档案只展示可操作的“生成清单/安排”入口，不后台悄悄写一组模板。
- 两端同时初始化模板仍每个 templateKey 至多一条；用户重复点击和丢响应重放安全。已删模板不被刷新悄悄重建。
- 修改孕期日期后先预览待调整的自动安排，再按明确确认更新；已完成、跳过、手动改期及自建产检不改。以各条的旧 revision 检测他端编辑，冲突不整批覆盖；记录部分成功并可恢复。
- 待产包的旧 `hospital_bag_items` 没有可信归属。不得正式页读入/自动上传/覆盖/清空；保留到 B3 来源确认。演示另用独立键，不影响正式队列。
- 与共同任务的关联留 C：预留 source ID 足够，不提前造两套完成进度或空任务按钮。

## 补充实施说明：批量动作如何沿用持久协议

模板初始化与改期不能只从页面直接 familyCall，再以顶层 ok 当成整批完成。可采用较简单的适配：**一条模板/一条改期对应一条持久 outbox 项**，外层批次仅汇总进度；服务端若保留数组 API，每次传单项也可。两人一次生成清单的规模无需另造复杂任务系统。

- 模板项保存稳定 templateKey、完整创建内容、成员/批次归属和 operationId；重复提交同一项仍走存在即保留的原子创建。单项成功后才移除该待办，失败保留；全部完成后拉取权威列表。用户手动改过或已删模板不能被重试覆盖。
- 改期项保存实体 ID、原 revision、预览时的目标日期；发送时从待办当前 expectedRevision 构建单项请求，避免外层冲突重提更新版本、内层 ops 仍带旧版本而无限冲突。部分成功不丢失败项。
- 数组响应中的单项 revision-conflict、not-eligible、transaction-failed 都必须反馈到该项的真实状态；顶层 ok 不代表单项成功。冲突保留原目标值供明确比较和重提，操作含义不能在重试时重新从最新界面推算。
- 聚合进度、刷新完整同步时间和“完成”提示基于真实单项结果；不同领域的待办和私人正文不能混进本页冲突卡。失效/换成员仍按现有 epoch 机制终止写回。

这只是对原持久化/部分失败要求的实现说明，不增加功能，也不要求必须采用某个函数名。
