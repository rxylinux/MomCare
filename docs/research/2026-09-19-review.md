# MomCare 当前工作区研究与审查

研究日期：2026-09-19。基准提交：`83fbbf3`，检查对象包含现有未提交修改。

结论：这是一个界面和单机记录功能已有基础、正在从 H5 产品向夫妻专用微信小程序迁移的项目。目前不能视为可交付的双人健康管理系统。主要问题集中在身份、数据真实性、失败处理和同步语义，新规划的六项功能大部分尚未实现。

## 1. 范围与验证方法

- 阅读项目说明、PRD、六功能规划、路由、主要页面、组件、三个 Store、请求封装及现有数据库 schema。
- 实际运行 H5 和微信小程序生产构建，二者均退出成功。
- 用真实 Vue/Pinia/Store/API 代码运行隔离探针；仅模拟 `uni` 的存储、请求和提示接口，没有调用真实后端，没有读写用户健康数据。
- 未运行微信开发者工具、双手机真机联调、真实 OCR/AI 服务、后端鉴权或平台上传；不将编译通过等同于这些场景验收通过。
- 没有修改业务源码。本次仅新增研究报告与探针脚本，构建更新了被 Git 忽略的 dist。
- 仓库原有未提交修改涉及 PRD、manifest、依赖、首页、登录页、health/report Store 与请求封装，另有未跟踪的六功能规划；这些均予以保留。

复现命令：

```sh
npm run build:h5
npm run build:mp-weixin
node docs/research/2026-09-19-probes.cjs
```

探针用于展示当前缺陷，断言的是已观察到的错误行为；它不是“产品测试通过”的证明。修复后应把对应场景改为正确行为的回归测试。

## 2. 当前系统组成

| 层级 | 实际实现 | 说明 |
| --- | --- | --- |
| 客户端 | UniApp、Vue 3.4.21、Pinia 2.1.7 | 25 个页面，四个 Tab；DCloud 使用 alpha 构建版本 |
| 健康数据 | stores/health.js | 孕周、档案、每日记录、产检日程、AI 次数；约 1051 行，承担过多职责 |
| 报告数据 | stores/report.js | 本地报告、远端同步、上传、解读、分类、批量操作 |
| 静态知识 | stores/staticData.js + 两份 JSON | 280 条每日内容、40 条周指南；没有来源、审校和更新时间字段 |
| 远程通信 | utils/api.js + 页面内直接 uploadFile | 仍硬编码 Cloudflare Worker 地址 |
| 后端 | 当前目录缺失 | 未找到 Worker 源码、D1 迁移、CloudBase 云函数、环境初始化与部署权限配置；.gitignore 明确忽略 worker/ |
| 数据模型 | db/schemas 下四个 JSON | 留有用户、报告、记录、文章 schema；不能据此认定存在已部署的 CloudBase 权限规则 |
| 工程验证 | npm 构建脚本 | 原仓库未发现自动化测试、测试脚本、lint 配置或 CI 验证流程 |

现有数据流：

```text
App.onLaunch -> silentLogin -> 演示身份与默认孕期 -> 本地统一存储
首页/记录页 -> health Store -> 本地 JSON
资料保存 -> 本地 JSON + 原 Cloudflare profile API
图片上传 -> 原 Cloudflare upload API -> 报告 Store -> 本地 JSON
AI 解读 -> 原 Cloudflare analyze API -> 结果与次数写回
App.onShow -> 云资料与报告拉取 -> 覆盖部分本地数据
```

健康记录和产检日程没有随资料同步上传。待产包另有本地存储。没有家庭实体、夫妻成员关系、角色权限、冲突解决或双端订阅机制。

## 4. 优先处理的问题

优先级定义：P1 为正式记录健康数据或双人试用前应解决；P2 为功能正确性、完整性与维护性问题。

### P1-1：网络失败被当作成功，空 AI 结果仍扣次数

证据：utils/api.js:84–86；stores/report.js:596–623。

所有请求的 fail 回调都返回 `200/code:0/data:{}`。报告 Store 只验证外层状态，接着将空对象标记为解读完成、将异常列表设为空，并扣一次额度。真实账号或其他非游客 token 下可复现；游客 401 是另一条缺 data 的分支，不能混称完全相同行为。

隔离实测：完全断网时 updateReport 返回 true；triggerAiPipeline 返回 true；ai_status 为 done，ai_result 为 {}，usedQuota 为 1，并出现“解读完成”。资料同步也会把同类失败识别为成功。

建议：保留网络错误；明确区分离线已暂存、等待同步、云端完成和业务失败。AI 成功必须通过结构验证，未知/缺失结果不能显示正常标记，额度以服务端实际成功的幂等任务为准。

### P1-2：演示数据进入正式存储，游客身份拦截真实登录

证据：stores/health.js:875–950；utils/api.js:50–63；App.vue:14–17。

首次启动自动创建孕 16 周、孕前 52 kg、当前 55.8 kg 等示例，直接写入 YUNTU_HEALTH_DATA。默认建档绕过真实预产期输入。示例字段为 bpSys/bpDia/fetalMovement/notes，但统计和表单读取 bp/fetal/note，导致体重有记录、血压无记录、胎动为零。

探针另证实：已有 guest_mock_token 时调用登录接口，无论输入的密码是什么，都直接返回游客身份且没有网络请求。这是客户端假登录，不是后端鉴权绕过。

建议：显式演示模式使用独立存储空间并清楚标注；正式模式从空档案开始。游客身份不应伪装为已认证 token；真实登录路径必须始终走真实认证。

### P1-3：主要图片上传入口使用错误 token 键

证据：pages/archives/components/UploadSheet.vue:162–168，对照 utils/api.js:3、19–21。

登录模块保存 momcare_token，上传组件读取 token；正常登录后通常不会携带当前有效 Authorization。Store 内另一个上传实现使用 getToken，两条实现已发生漂移。

建议：将上传和认证统一到服务模块，并用网络适配器探针验证请求头。还需真实后端联调确认上传、归档、解读完整链路。

### P1-4：云端全量替换会丢失本地报告/离线修改

证据：stores/report.js:229–243、340–372、375–412。

存在本地创建报告的合法分支，但同步无条件用服务器列表替换本地数组并持久化；无待同步队列、版本或删除标记。探针创建一条本地报告后模拟合法空云列表，本地内存与持久化报告都变为零。此前假成功的离线修改同样可能被下次同步覆盖。

建议：明确服务端记录与本地草稿身份，保留待同步操作；以稳定 ID、版本和冲突策略合并，不能对含待同步数据的集合直接全量覆盖。

### P1-5：隐私页的存储、备份和删除承诺与代码不符

证据：pages/profile/privacy.vue:8–17、74–112；stores/health.js:188–193；stores/report.js:84–88。

页面写死 128 MB、11 份报告、“已同步”和 AES-256 加密；实际客户端只序列化 JSON 写入 uni 存储，没有对应的应用层加密实现。不能从当前目录判断未知后端是否加密。注销和清理只弹“操作完成”，没有执行删除；导出仍显示开发中。

建议：状态和容量来自真实数据；未实现能力应明确显示不可用。先实现可验证的导出、恢复、删除和备份，再作隐私承诺。

### P1-6：账户切换没有本地数据边界

证据：health/report 使用固定 YUNTU 存储键；pages/profile/index.vue:108–112。

退出只删除 token 与 momcare_user，没有清理 Store 和健康/报告存储，也没有按账号或家庭命名空间隔离。新账号同步只覆盖部分内容，健康记录和产检日程会残留。夫妻产品需要显式共享同一家庭，不能依赖同设备缓存混用模拟共享。

### P1-7：存储失败被吞掉

证据：两个 Store 的 _saveStorage；health.js:572–575。

模拟存储配额不足时，saveRecord 正常 resolve，内存已更新，但持久化完全没有变化。用户重启后可能丢失刚才“保存”的内容。

建议：持久化失败可观测并反馈给调用方；避免先更新内存再隐瞒写盘失败，或明确保留未保存状态。

### P2-1：日期与产检日程不同步

- `today = computed(() => new Date())` 没有响应式依赖，首次求值后缓存，不能实现零点自动刷新（health.js:270）。
- 修改孕期资料保存时不重新计算已有日程；演示日程也会保留（pregnancy-info.vue:326–381）。不能简单清空重建，否则会丢失已完成检查，需要迁移未完成安排。
- health Store 的 isDueDate 将日号与 today 比较，而非 dueDate（health.js:417–420）。此辅助函数有确定缺陷，但日历组件使用自己的正确比较函数，不能据此声称日历标记一定错误。
- 第一个模板标注孕 7 周，却使用 42 天偏移；按同 Store 的孕周公式得到 6 周（health.js:73–75）。需统一“第几周”和“已满几周”的表达。

### P2-2：单份分类后，报告未移入已归档列表

证据：pages/archives/classify.vue:215–228；stores/report.js:400–409。

分类页调用 updateReport 修改 archive_status，但没有迁移两个数组。探针证实记录状态为 archived 时仍留在 unarchivedReports。真实账号可能等下次云同步才修正；游客模式又跳过同步。

### P2-3：静态内容加载与小程序兼容性待修复

证据：stores/staticData.js:10–34。

静态 JSON 通过 `/static/...` 网络请求加载，依赖 H5 的站点路径语义，小程序应改为打包 import 或适当的文件读取方案并真机验证。另一个已复现的问题是返回 404 时仍设 loaded=true、loadError=false，后续不再加载。

### P2-4：小程序发布准备未完成

当前 manifest 的 appid 为 touristappid。构建结果无分包，packOptions.ignore 为空。精确文件总量 10,396,634 bytes（9.915 MiB），其中 logo.png 4,079,741 bytes，iOS 专用 mobileconfig 5,441,372 bytes，二者约占 91.6%。

应排除 H5/iOS 专属资源、压缩 logo，再由真实 AppID 的微信开发者工具确认包体规则与上传结果。构建器生成的 bigPackageSizeSupport=true 不能单独证明账号已具备对应发布能力；本次没有把包体风险写成已观察到的平台拒绝。

构建另外提示 health/report 循环 chunk、Sass legacy JS API 弃用、小程序 h2 标签选择器不支持。没有导致本次编译失败，但说明双端适配尚未验收。

## 5. 六功能规划需要修订的前提

1. **纯本地存储与夫妻跨设备实时共享不是等价架构。** 要共享，需要受控的共同后端或显式同步通道；本地适合作缓存和离线操作队列。
2. **“终身免费”不能作为交付保证。** 查阅的腾讯云官方价格说明提供有限额、需按期续期的免费体验环境，并存在功能及发布条件限制；应按实际账号环境核实，AI 调用也需单独预算。[腾讯云价格文档](https://cloud.tencent.cn/document/product/876/75213)
3. **胎动规则不能直接照规划硬编码为正常判定。** 文档拟定“5 分钟合并、每小时达到 3 次即正常、少于 3 次先喝水休息”，缺少适用人群和临床依据。NHS 的公开指导强调个体日常模式，没有统一正常次数；减少、停止或模式改变应立即联系产科。这足以说明规划中的统一绿灯判定不能未经专业审查上线。[NHS 胎动指导](https://www.nhs.uk/pregnancy/keeping-well/your-babys-movements/)
4. **AI 缓存不能自动升级为“权威库”。** 保留生成来源、证据、模型版本、时间和未审校标记；药物等不能简单靠通用红黄绿卡片作决策。“以主任医师口吻”不是准确性或审核保证。
5. **估重和宫缩工具应先明确规则边界。** 单位、测量孕周、公式版本、参考曲线、适用范围、后台恢复及异常输入必须可测试；估重呈现为估算而非诊断，计时器不应成为求助的唯一条件。具体医学内容需要适用地区的专业审校。
6. **两人自用无需先建设 VIP。** 当前旧会员逻辑与目标无关，应优先真实建档、可靠记录、报告备份和家庭授权。体验成员范围也不能替代服务端家庭权限控制。

## 6. 建议实施顺序与验收条件

### 第一阶段：先确保记录可信、失败可见

- 拆开演示与正式模式，去掉网络假成功，统一 token 与上传逻辑。
- 修复存储失败、账号隔离、报告归档数组、日期刷新及产检迁移。
- 移除不真实的加密、同步、删除和容量展示，补基础导出/恢复。
- 验收：断网解读不成功且不扣次数；断网保存明确提示待同步；重启保留记录；切换账号不串数据；导出可恢复；云端空响应不会吞本地草稿。

### 第二阶段：完成微信身份和家庭共享

- 保留 Vue 页面与 Pinia，抽离 auth、health repository、report repository、content loader 和时钟计算服务。
- CloudBase 建立家庭、成员、孕期档案；一份孕期归属一个家庭，记录带实际操作者，角色切换不能改变授权。
- 使用服务端可信 OpenID 建立成员关系；云函数验证家庭权限，AI/OCR 凭据仅留服务端。
- 数据带 schemaVersion、revision、updatedAt；离线操作有幂等 ID 和重试状态；图片引用可持久恢复。
- 验收：两台设备交叉创建/修改/删除，恢复网络后收敛；非家庭成员被拒绝；图片重启后可访问；AI 超时重试不重复扣费。

### 第三阶段：补齐可交付的小程序体验

- 清理包体与平台专属代码，修复静态数据加载，配置真实 AppID 和环境。
- 真机验证导航、弹层、相机相册、后台恢复、缓存、网络失败和字体样式。
- 产检通知作为单独能力实现并验证，避免把页面倒计时称为消息提醒。

### 第四阶段：分批增加六项功能

- 先交付少量有来源、可维护的饮食词条、爸爸任务和工具入口，避免先追求 500 条规模。
- 再加入可追溯的估重计算和原始胎动事件记录。
- 最后交付经专业审校的宫缩提示和 AI 兜底；规则与时钟算法使用纯函数，覆盖边界和后台恢复。

建议保留已有页面、日历、历史记录展示和大部分样式；集中重构身份、持久化、网络和领域规则。当前最值得投入的是让已有功能真实可靠，再扩展夫妻协同和工具箱。
