## 阶段 A：先修 F1–F3，完成后交 Codex 审核

### F1：旧计时数据安全找回

1. 检测旧固定键 active/history/finish queue/stop queue 的存在，计时页面提供持久可见的“待确认旧记录”入口。未确认前不展示正文、不上传，不把旧记录自动并到当前成员。检测读取异常应如实提示。
2. 提供显式归属确认与原始数据导出/保留通路。确认提示应说明无身份旧记录无法自动证明所有者；若设计还存在不可判定归属，保留导出，不猜身份。
3. 有服务端 sessionId/recordId 的旧记录，续跑前验证真实云端记录归属及状态，不仅用点击确认赋予操作权限；无法验证时保留待处理，不发 mutation。无云端 ID 的离线草稿仅在明确确认归属后按当前完整作用域迁入。
4. 迁移保持 localRef、操作 ID、点击顺序、finish/stop 时间和显式 null；写入/验证目标耐久成功之前不得删除、清空或覆写旧字节。重复确认、部分写失败、重启必须幂等，不产生双会话/双操作；原数据保全可优先使用原始字节备份。
5. 新旧记录同时存在不得互相覆盖：提供清晰冲突提示和可保全的处理方式。不得只加一个按钮而无可用业务通路。
6. 验收：旧版真实键形状的进行中会话、离线点击、finish/stop 队列；未确认零上传；已有云端 ID 的不同所有者拒绝续跑；目标写失败/冷重启/重复确认；新旧 active 冲突；确认后准确续跑与实际页面展示。仅临时 uni storage 夹具。

### F2：恢复闸按域约束，删除与刷新分开反馈

1. EFW 云端读不依赖胎动/宫缩缓存完整性；计时闸按相应数据域限制，不让一个域异常阻止无关域恢复。共享 retryPending 应独立处理允许的域并如实返回被阻断域，保持会话守卫与顺序。
2. EFW 删除云端成功后明确反映删除成功；刷新失败不能误报删除失败，不能保留可再次误删的旧活行。对会话切换仍需丢弃旧响应，勿为刷新修复跨身份写入。
3. EFW 页面应消费拉取失败结果，给出可见失败/重试状态。
4. 验收：胎动 corrupt / 宫缩正常及反向场景；EFW 读正常；删除成功+刷新失败；删除本身失败；await 中切身份；生产页入口真实调用，不只测 helper。

### F3：OCR 截断的真实覆盖披露

1. 持久化能区分 OCR 已识别页与实际送入模型内容的覆盖信息，以及文本截断状态。兼容现有无新字段结果，旧结果不得推断“完整内容”。长文截断时不得显示“已分析全部附件”。
2. 详情/结果页准确披露截断；视觉模式、不截断 OCR、元数据模式保持正确。更新 familyAiView 和导出/恢复嵌套键白名单、类型/大小/一致性校验，同步增加所需包依赖，防新字段使正常导出降诊断包。不要发送供应商秘密或调试内部字段。
3. 复用旧 OCR 缓存也应按已知截断证据处理；不能把所有 pageFileIds 当作全部进入模型的证明。
4. 验收：第一页 >2000 字符、第二页独有标记，抓实际 provider prompt 并核对持久化结果、两个页面及实际导出包字节；截断不得声称全部内容分析；不截断/视觉/metadata/旧结果读侧兼容；冻结恢复字段接受与非法字段拒绝。
